# MANZO Architecture

MANZO is a Winamp-inspired macOS music player built with a strict process boundary: a Rust staticlib (`manzo-core`) handles all audio decode, DSP processing, and FFT computation, while a Swift/AppKit application (`ManzoApp`) owns the UI, window management, and Metal rendering. The two halves communicate exclusively through a thin C FFI surface of 13 functions, generated by cbindgen and bridged into Swift via an Objective-C bridging header. The target is macOS Sequoia 15+, Apple Silicon (arm64) only.

## Data Flow

### Audio Playback

1. Swift calls `manzo_open(path)` → Rust allocates a `ManzoHandle` and opens the file via the mpg123 feed API (`mpg123_open_feed`).
2. Swift calls `manzo_play(handle)` → Rust starts an independent audio thread. The thread feeds 4096-byte chunks to mpg123 (`mpg123_feed`), reads float32 PCM (`mpg123_read` with `MPG123_FORCE_FLOAT`), and trims exactly 529 samples of decoder priming delay for gapless playback.
3. PCM samples flow float32 end-to-end — no int16 intermediate conversion — through the 10-band dual-biquad IIR EQ, then into a cpal CoreAudio output callback. `AVAudioMixerNode` handles volume and pan.
4. Swift calls `manzo_set_eq(handle, gains, preamp)`, `manzo_set_volume`, and `manzo_set_pan` in response to UI control events. These are applied within the next audio buffer period.
5. Swift polls `manzo_get_position(handle)` on a 100 ms timer to update the seek bar display. `manzo_get_state(handle)` is polled at the same interval to detect natural EOF (state 4 = ENDED) and auto-advance the playlist. `manzo_get_duration(handle)` is read at open time to set the seek bar range.

### Spectrum Analyzer

1. The Rust audio thread maintains a float32 FFT magnitude buffer alongside playback.
2. Swift calls `manzo_get_spectrum(handle, out_buf, count)` → Rust writes normalized magnitudes (0.0–1.0) into a shared `UnsafeMutablePointer<Float>`.
3. The Metal layer wraps that pointer in an `MTLBuffer` with `.storageModeShared` — zero CPU copy per frame.
4. A `CADisplayLink` on a background thread drives the `MTKView` render loop. The Metal vertex shader reads the `MTLBuffer` directly and produces bar quads; the fragment shader applies SDF single-pass Gaussian bloom (3σ extension, analytical glow per fragment).
5. Peak-hold values are updated at ~10 fps (not every render frame) and drawn as a second vertex pass with `sigma * 2.0`.

### Online Streaming (Phase 9)

URL input → yt-dlp sidecar (`Contents/MacOS/yt-dlp`) → stdout pipe → Rust audio pipeline (same float32 path as local MP3).

## Build System

The build chain is driven entirely by Xcode:

1. **Xcode run-script phase** ("Build Rust manzo-core") runs before compilation:
   - `cargo build --release --target aarch64-apple-darwin`
   - `cbindgen --config cbindgen.toml --output manzo_core.h`
   - Output declared: `libmanzo_core.a` at `manzo-core/target/aarch64-apple-darwin/release/`
2. **Xcode linker** links `libmanzo_core.a` via `OTHER_LDFLAGS = -lmanzo_core` and `LIBRARY_SEARCH_PATHS` pointing to the Cargo release output directory.
3. **Swift bridging header** at `ManzoApp/ManzoApp-Bridging-Header.h` includes `manzo_core.h` — making all 13 functions callable from Swift with no `@_silgen_name` decoration.

Build configuration: `ARCHS = arm64`, `VALID_ARCHS = arm64`, `MACOSX_DEPLOYMENT_TARGET = 15.0`, `SWIFT_VERSION = 5.10`.

**Cargo.toml crate configuration:** `crate-type = ["staticlib", "rlib"]` — `staticlib` produces `libmanzo_core.a` for Xcode linking; `rlib` enables `cargo test` to run unit tests (a pure staticlib cannot be linked by the test harness). Dependencies include `mpg123-sys`, `cpal`, `libc`, and `rustfft = "6"` for the 1024-point FFT pipeline.

## Rendering Architecture

### Window Hierarchy

```
NSWindow (.borderless, .resizable, isOpaque=false)
└── NSVisualEffectView (.behindWindow)   ← EXACTLY ONE per window
    ├── [Inner panels]                   ← CALayer-only (wantsLayer=true, isOpaque=false)
    │   └── NeoAeroLayer 5-stack         ← CAGradientLayer + CAReplicatorLayer
    ├── Spectrum MTKView                 ← Metal, rgba16Float, P3 colorspace
    └── [Transient overlays]             ← NSVisualEffectView(.withinWindow) ONLY
```

The single `.behindWindow` `NSVisualEffectView` at the window root captures the desktop compositor buffer and provides refraction. Inner panels are semi-transparent CALayer subtrees (alpha ≈ 0.35–0.4) that appear as glass-on-glass without a second blur pass. Nesting a second `.behindWindow` view produces a double-blur artifact (milky/washed-out) — this constraint is hard.

### Neo-Aero Layer Stack (per panel)

Each panel chrome element assembles five CALayers:
1. **Base gradient** — `CAGradientLayer`, aqua-teal top → deeper teal bottom, P3 colors
2. **Specular band** — `CAGradientLayer`, white 50% opacity fading over top 52% of height
3. **Lower glow** — `CAGradientLayer`, white 12% opacity at bottom 25%
4. **Rim highlight** — `CALayer` with 1 pt white border (45% opacity), inset 0.5 pt
5. **Wet-floor reflection** — `CAReplicatorLayer` with Y-flip transform, `instanceAlphaOffset = -0.5`, `CAGradientLayer` fade mask

Static panels use `shouldRasterize = true` + `rasterizationScale = 2.0` (Retina). 30 elements on M-series measures < 0.8 ms GPU time.

### Spectrum Renderer

- `MTKView` with `CAMetalLayer.pixelFormat = .rgba16Float` and `CAMetalLayer.colorspace = displayP3` (must be set explicitly — MTKView does not auto-configure P3).
- `wantsExtendedDynamicRangeContent = true` — bar fragment values > 1.0 render as true HDR highlights on ProMotion displays.
- **v1:** SDF single-pass bloom — bar quads extended by 3σ, analytical Gaussian glow per fragment. No extra textures or second pass.
- **v2 (when cross-bar glow is needed):** Two-pass MPS bloom via `MPSImageGaussianBlur(sigma: 6.0)` on a half-resolution threshold texture. Total GPU time on M1: < 0.6 ms.
- Render loop: `CADisplayLink` on a background thread. Main thread never blocked by GPU work.

## Critical Constraints

These constraints are validated by spike experiments and must not be violated:

| Constraint | Consequence of violation |
|---|---|
| Exactly one `.behindWindow` `NSVisualEffectView` per `NSWindow` | Second instance → double-blur artifact (milky/grey compositor output) |
| All inner panels: `CALayer`-only, `isOpaque = false`, no nested `NSVisualEffectView` | Silent visual degradation; nested vibrancy produces wash-out |
| `NSWindow.isOpaque = false` set before `orderFront` | Silent failure: compositor skips behind-window buffer; no glass effect, no crash |
| `NSWindow.canBecomeKey` overridden to `true` on `.borderless` window | Window receives no keyboard events |
| All brand colors via `CGColor(colorSpace: .displayP3)` — no sRGB | P3 values silently clamped to sRGB gamut; colors appear muted |
| `MTKView`: `CAMetalLayer.colorspace` must be set explicitly | P3 colors silently clamped to sRGB; no error thrown |
| `MTKView` pixel format: `.rgba16Float` | `bgra8Unorm` cannot represent values > 1.0; bloom HDR impossible |
| `shouldRasterize = true` requires `rasterizationScale = 2.0` | Blurry rasterized layers on Retina displays |
| Float32 pipeline end-to-end — no int16 conversion | Precision loss and unnecessary CPU copies in audio path |
| mpg123 gapless: trim exactly 529 samples of decoder priming delay | Audible silence gap between tracks at boundaries |
| FFI surface: exactly 13 `manzo_*` functions | Additional symbols require cbindgen re-run and bridging header update |
| Spectrum `CADisplayLink` render loop on background thread | Main thread GPU work → UI jank / dropped frames |
| `crate-type = ["staticlib", "rlib"]` — both required | `staticlib`-only: `cargo test` link fails; `rlib`-only: Xcode cannot link `libmanzo_core.a` |
