# MANZO — Development Guide

This document covers local setup, build commands, code style, and contribution conventions for active development on MANZO.

## Local Setup

### Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| macOS | Sequoia 15.0+ | Required for AppKit/Metal APIs used |
| Xcode | 16.0+ | Swift 5.10; provides `xcodebuild`, Metal shader compiler |
| Rust toolchain | stable | Install via [rustup](https://rustup.rs/) |
| `aarch64-apple-darwin` target | — | `rustup target add aarch64-apple-darwin` |
| cbindgen | latest stable | `cargo install cbindgen` |
| xcodegen | latest stable | `brew install xcodegen` |

Apple Silicon (arm64) only — x86_64/Intel Macs are not supported and the build configuration explicitly sets `ARCHS = arm64`.

### Fork and Clone

```bash
git clone <repository-url> MANZO
cd MANZO
```

### Install Rust target and cbindgen (one-time)

```bash
rustup target add aarch64-apple-darwin
cargo install cbindgen
```

### Generate the Xcode project

The Xcode project (`ManzoApp.xcodeproj`) is generated from `ManzoApp/project.yml` via xcodegen. The generated project file is checked in, but if you modify `project.yml` you must regenerate:

```bash
cd ManzoApp
xcodegen generate
```

### Open in Xcode

```bash
open ManzoApp/ManzoApp.xcodeproj
```

### Build

Press `Cmd+R` in Xcode. The pre-build run-script phase automatically:
1. Runs `cargo build --release --target aarch64-apple-darwin` inside `manzo-core/`
2. Regenerates `manzo_core.h` via `cbindgen --config cbindgen.toml --output manzo_core.h`
3. Links `libmanzo_core.a` into the Swift app via `-lmanzo_core`

No manual `cargo build` is required for normal Xcode-driven development.

### Verify the build

On first launch the app logs:

```
MANZO Phase 1: FFI smoke test passed — manzo_play returned 0
```

This confirms the Rust staticlib linked correctly and all 13 FFI symbols resolved.

## Code Style

### Rust

No `rustfmt.toml` is present; the project uses Rust stable defaults. Run the formatter before committing:

```bash
cd manzo-core
cargo fmt
```

Run the linter:

```bash
cd manzo-core
cargo clippy --target aarch64-apple-darwin -- -D warnings
```

### Swift

No `.swiftformat` or `.swiftlint.yml` is present. Follow the Xcode default Swift style:
- 4-space indentation (consistent with `cbindgen.toml` `tab_width = 4`)
- No trailing whitespace
- Opening brace on the same line as the declaration

### Project-specific style rules

These constraints come from spike validation and must be respected in all Swift code:

- **P3 colors only.** Use `CGColor(colorSpace: .displayP3, components: [...])` for every brand color — never `NSColor` sRGB convenience initializers.
- **One `NSVisualEffectView` per window.** The single `.behindWindow` view lives at the window root. Never add a nested `NSVisualEffectView` with material `.behindWindow` inside the view hierarchy.
- **CALayer-only inner panels.** Set `wantsLayer = true` and `isOpaque = false` on inner panel views; do not wrap them in `NSVisualEffectView`.
- **Native Window Docking.** Use `addChildWindow(_:ordered:)` for syncing panel movement rather than tracking window frames.
- **`shouldRasterize` requires scale.** If you set `layer.shouldRasterize = true`, always also set `layer.rasterizationScale = 2.0` for Retina display correctness.
- **Float32 audio pipeline.** All audio data between mpg123, the DSP chain, and cpal must stay as `Float32` — no `Int16` intermediate conversions.

## FFI Development

The Rust/Swift boundary is the most sensitive area of the codebase. Follow these rules when modifying FFI code:

1. **Declare new public functions with `#[no_mangle]` and `extern "C"`.** Add them to `manzo-core/src/lib.rs` and annotate with doc comments — cbindgen picks up doc comments and emits them into the C header.
2. **Run cbindgen after any FFI change.** Either run `cargo build` (which triggers `build.rs`) or run `cbindgen` manually. The bridging header at `ManzoApp/ManzoApp/ManzoApp-Bridging-Header.h` `#include`s `manzo_core.h` — it does not need manual editing.
3. **Keep the FFI surface at exactly 13 functions for v1.** `manzo_get_state` and `manzo_get_duration` were added in Phase 3, bringing the total to 13. Adding symbols requires a cbindgen re-run and Xcode clean build. Document any new function in `docs/ARCHITECTURE.md` FFI Surface table (updated to reflect 13 functions).
4. **Opaque handles are caller-owned.** `manzo_open` returns a `*mut ManzoHandle` that Swift owns and must pass to `manzo_close`. Never free it from Rust outside of `manzo_close`.

- **All `cargo test` tests must pass** before opening the PR.

- **Reference the requirement ID** from `.planning/REQUIREMENTS.md` in the PR description (e.g., "Implements AUDIO-01, AUDIO-04").

## Critical Development Constraints

These constraints are validated by spike experiments. Violating them produces hard-to-debug visual or audio artifacts rather than compile errors:

| Rule | Consequence if violated |
|------|------------------------|
| One `.behindWindow` `NSVisualEffectView` per `NSWindow` | Double-blur artifact — milky/grey compositor output |
| `NSWindow.isOpaque = false` must be set before `orderFront` | No glass effect; compositor silently skips behind-window buffer |
| `NSWindow.canBecomeKey` must be overridden to `true` on `.borderless` window | Window receives no keyboard events |
| `CAMetalLayer.colorspace` must be set explicitly on `MTKView` | P3 colors silently clamped to sRGB — no error thrown |
| `MTKView` pixel format must be `.rgba16Float` | Cannot represent values > 1.0; HDR bloom impossible |
| mpg123 gapless: trim exactly 529 samples of decoder priming delay | Audible silence gap between tracks |
| Float32 audio pipeline end-to-end | Precision loss and unnecessary CPU copies |
| `shouldRasterize = true` requires `rasterizationScale = 2.0` | Blurry rasterized layers on Retina displays |

See `docs/ARCHITECTURE.md` — Critical Constraints for the complete table.
