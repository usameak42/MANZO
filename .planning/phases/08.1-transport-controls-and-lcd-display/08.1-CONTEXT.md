# Phase 8.1: Transport Controls and LCD Display - Context

**Gathered:** 2026-04-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Add the Winamp-style LCD information display, transport controls, seek bar, and volume/pan
sliders to the main 275×116 window — wired to the existing Rust FFI. All controls follow
canonical Winamp pixel positions extracted from `draw_main.cpp`. The spectrum view is
relocated from its current bottom-anchored position to Winamp's visualization area band.

**In scope:**
- `ManzoLCDView` — black-background LCD panel with CATextLayer fields (title, time, bitrate, kHz, stereo)
- `ManzoSeekBar` — custom CALayer seek bar (live seek while dragging)
- `ManzoSlider` — reusable horizontal CALayer slider for volume and pan
- `ManzoTransportButton` — reusable NeoAero glass button for the transport row
- Transport row: prev, play/pause toggle, stop, next (wired); eject, shuffle, repeat (placeholders)
- `PlaylistManager.prev()` — new method for smart-prev behavior
- Spectrum view repositioned from bottom-anchored to Winamp's y=57–87 band
- 100ms poll timer extended to update seek bar position and title scroll tick
- Play/pause state read from `manzo_get_state` on every poll tick

**Out of scope:**
- EQ slider UI — still a separate phase
- Shuffle/repeat logic — placeholders only, no-op in Phase 8.1
- CD audio playback — CoreAudio/IOKit CD API deferred to v2
- Visualizer mode switching — spectrum stays fixed

</domain>

<decisions>
## Implementation Decisions

### D-01: Canonical Winamp Pixel Layout

All new controls positioned using exact Winamp coordinates from `draw_main.cpp` (y from
top of window, x from left). Window remains 275×116 pt fixed (Phase 5 D-03 unchanged).

| Control | x range | y range | Size (pt) |
|---------|---------|---------|-----------|
| Play icon (state indicator) | 26–35 | 28–37 | 9×9 |
| Time digits | 36–100 | 26–39 | 64×13 |
| Song title (scrolling) | 111–265 | 25–35 | 154×10 |
| Bitrate + kHz text | 111–176 | 43–49 | 65×6 |
| Mono/Stereo indicators | 212–268 | 41–53 | 56×12 |
| Volume slider | 107–175 | 57–70 | 68×13 |
| Pan slider | 177–215 | 57–70 | 38×13 |
| Seek bar | 16–264 | 72–82 | 248×10 |
| Transport buttons (4 wired) | 16–130 | 88–106 | 114×18 |
| Eject (wired), Shuffle, Repeat (placeholders) | 136–238 | 89–105 | 102×16 |

Source: `Winamp/Src/winamp/draw_main.cpp` — functions `draw_time`, `draw_buttonbar`,
`draw_positionbar`, `draw_volumebar`, `draw_panbar`, `draw_bitmixrate`, `draw_monostereo`.

### D-02: Control Placement Strategy

All new Phase 8.1 NSView subviews are added **directly to ManzoRootView** (not to
`titleView`/`bodyView`/`statusView`). Reason: transport buttons span the
bodyView/statusView boundary (y=88–106 overlaps the statusView strip at y=102–116), so
constraining to a single panel view is not possible.

Constraints use **NSLayoutAnchor relative to ManzoRootView.topAnchor and
ManzoRootView.leadingAnchor** with constant pixel values from D-01. This aligns with the
established NSLayoutAnchor pattern (Phase 5 D-10) while using top-referenced positioning
that matches Winamp's y-from-top convention.

Example pattern:
```swift
lcdView.topAnchor.constraint(equalTo: rootView.topAnchor, constant: 14),
lcdView.leadingAnchor.constraint(equalTo: rootView.leadingAnchor),
lcdView.trailingAnchor.constraint(equalTo: rootView.trailingAnchor),
lcdView.heightAnchor.constraint(equalToConstant: 43),
```

### D-03: Spectrum View Relocation

The ManzoSpectrumView constraints are updated in Phase 8.1 to match Winamp's visualization
band:
- **Remove** existing constraints (225×32, centered, bottomAnchor in bodyView)
- **Add** new constraints: `topAnchor = bodyView.topAnchor + 43`, height = 32, width = 107
  - In bodyView coords: y=43 from bodyView top = y=57 from window top (bodyView starts at y=14)
  - Width 107 pt: left portion of the viz+sliders band, matching Winamp's layout
- **NeoAero chrome mask** must be reapplied via `applySpectrumChromeMask` after
  the new frame is available (call `bodyView.layoutSubtreeIfNeeded()` first)

Alternatively, the spectrum can remain in bodyView with updated constraints, or be moved
to ManzoRootView. **Planner: choose the cleanest approach given the existing code.**

### D-04: ManzoLCDView

`ManzoLCDView : NSView` — placed at topAnchor + 14, full width, height = 43.

Five CATextLayer fields with exact Winamp-relative positions:
- `titleLayer` — x=111, y=25, 154×10. Winamp green P3 font.
- `timeLayer` — x=36, y=26, 64×13. Larger monospaced digits.
- `bitrateLayer` — x=111, y=43, 45×6. Small digits (e.g. "128").
- `kHzLayer` — x=156, y=43, 20×6. Small digits (e.g. "44").
- `stereoLayer` — x=212, y=41, 56×12. "STEREO" / "MONO" text.

Background: `CGColor(colorSpace: .displayP3, components: [0, 0, 0, 1])` (pure black).
Text color (all fields): P3(0.18, 0.82, 0.18, 1.0) — Winamp LCD green.
Font: `NSFont.monospacedSystemFont(ofSize: 8, weight: .medium)` for time/bitrate/kHz.
Title: system font, size 8, regular weight (Winamp used a custom 5px bitmap font; closest
  native approximation is small monospacedSystem).

### D-05: Title Scrolling

Timer-based pixel shift via the existing 100ms poll timer in AppDelegate:
- Each poll tick: shift `titleLayer.position.x` left by 0.5pt (smooth at 10fps)
- When `titleLayer.frame.maxX < titleLayer.superlayer!.bounds.minX`: reset position to
  `titleLayer.superlayer!.bounds.maxX` (tile seamlessly by appending " *** " spacer)
- **Only scroll when title text width > 154pt** (the available display area). Static otherwise.
- On track change: reset position to 0, rebuild title string.

### D-06: Time Display — Toggleable Elapsed / Remaining

- Default state: show elapsed (`manzo_get_position` value)
- `timeLayer` area has an `NSTrackingArea` — `mouseDown` toggles a Boolean flag
  `isShowingRemaining: Bool` in ManzoLCDView (or AppDelegate, planner's discretion)
- When `isShowingRemaining = true`: display `-(duration - position)` with a minus prefix
- 100ms poll timer reads the flag each tick and updates `timeLayer.string`
- Requires track `duration` from `PlaylistManager.trackAt(currentIndex)?.duration`

### D-07: ManzoSeekBar

`ManzoSeekBar : NSView` at x=16, y=72, width=248, height=10.

```swift
// Layer structure
layer.backgroundColor = P3 dark (same as LCD background)
fillLayer: CALayer     // green, width = (position / duration) * 248
thumbLayer: CALayer    // 3×10, bright P3 green, left-edge at fill end
```

Mouse handling:
- `mouseDown`: compute `t = event.x / 248 * duration`, call `manzo_seek(handle, t)` immediately
- `mouseDragged`: compute `t`, call `manzo_seek(handle, t)` live on every event (**D-user: live seek**)
- No mouseUp required (seek is live)

100ms poll timer resets `fillLayer.frame.width` and `thumbLayer.frame.origin.x` when NOT
dragging. Set a `isDragging: Bool` flag on mouseDown, clear on mouseUp, so the timer
doesn't fight the drag.

### D-08: ManzoSlider (Volume + Pan)

Reusable `ManzoSlider : NSView` with `min`, `max`, `value: Float` properties.

Volume: frame at x=107, y=57, 68×13. Range 0–255. Initial value from config.
Pan: frame at x=177, y=57, 38×13. Range -127–+127. Center (0) = thumb at midpoint.

Layer structure same as ManzoSeekBar. On value change:
- Volume: `manzo_set_volume(handle, UInt32(value))`
- Pan: `manzo_set_pan(handle, Int32(value))`

### D-09: ManzoTransportButton

`ManzoTransportButton : NSView` with:
- `NeoAeroLayerFactory` glass layer as base (same factory as Phase 6)
- `CATextLayer` label in P3 green, small font (size 9)
- `NSTrackingArea` for hover + press states
- Hover: reduce rim highlight alpha by 0.2
- Press: `shouldRasterize = false` + `shouldRasterize = true` to refresh specular band briefly

Button sizes (matching Winamp's d1/d2 widths from `draw_buttonbar`):
```
Prev:  23×18 pt  at x=16,  y=88
Play:  23×18 pt  at x=39,  y=88
Stop:  23×18 pt  at x=62,  y=88
Next:  22×18 pt  at x=85,  y=88
```
Label unicode: ⏮ ▶/⏸ ■ ⏭ (play/pause toggles based on MANZO_STATE_*)

Eject placeholder: 22×16 at x=136, y=89, label "⏏" — wired to `openFilePicker()`
Shuffle placeholder: 47×15 at x=164, y=89, label "SHF" — no-op
Repeat placeholder: 28×15 at x=210, y=89, label "REP" — no-op

### D-10: Play/Pause Toggle State

Play/pause button state is driven by the 100ms poll timer:
- `MANZO_STATE_PLAYING (1)`: label shows ⏸, press calls `manzo_pause(handle)`
- `MANZO_STATE_PAUSED (2)` or `MANZO_STATE_STOPPED (3)`: label shows ▶, press calls `manzo_play(handle)`
- `MANZO_STATE_ENDED (4)`: handled by existing `pollPlaybackState` auto-advance; play button shows ▶

If no handle (empty playlist): play button press triggers `openFilePicker()` OR is a no-op
(planner's discretion).

### D-11: Smart Prev Button

`PlaylistManager.prev()` — NEW method to add:
```swift
func prev() -> PlaylistTrack? {
    guard currentIndex > 0 else { return trackAt(0) } // stay at first
    currentIndex -= 1
    return tracks[currentIndex]
}
```

Smart prev logic in the button handler:
```swift
// On prev button press:
let elapsed = manzo_get_position(handle)
if elapsed > 2.0 {
    manzo_seek(handle, 0.0)          // restart current track
} else {
    guard let prevTrack = playlistManager.prev() else { return }
    jumpToTrack(at: playlistManager.currentIndex) // existing method
}
```

### D-12: Poll Timer Extensions

The existing `pollPlaybackState()` method is extended (NOT replaced) to:
1. Read `manzo_get_position(handle)` → update `ManzoSeekBar.currentPosition`
2. Tick title scroll offset in `ManzoLCDView`
3. Update `timeLayer.string` in `ManzoLCDView` based on elapsed/remaining toggle
4. Update `play/pause button` label based on current `manzo_get_state`

All additions go inside the existing `pollPlaybackState` `@objc` method.

### Claude's Discretion

- Whether `ManzoLCDView` owns the scroll-tick state or AppDelegate does
- Whether `ManzoSeekBar`/`ManzoSlider` call FFI directly or via a delegate/closure
- Exact `isShowingRemaining` toggle ownership (view vs AppDelegate)
- Whether spectrum relocation stays in `bodyView` or moves to `ManzoRootView`
- Play button press when no handle: no-op vs open file picker
- Exact NeoAero glass variant for transport buttons (full 5-layer vs simplified 2-layer for the smaller 23×18 buttons)

<specifics>
## Specific Ideas

- **Winamp LCD green:** `P3(0.18, 0.82, 0.18, 1.0)` — derived from sampling Winamp's classic
  green-on-black LCD. The P3 values are within sRGB gamut so numerically equivalent to the
  sampled sRGB color.
- **Transport button d1/d2 widths** from `draw_buttonbar`:
  ```
  d1 = { 0, 23, 46, 69, 92 }  // width of each button's first section
  d2 = { 23, 46, 69, 92, 114} // start of next button
  ```
  Prev: 0→23 (23pt), Play: 23→46 (23pt), Stop: 46→69 (23pt), Next: 69→92 (23pt), Eject: 92→114 (22pt)
  Buttons start at x=16 (8+8 from draw_buttonbar).
- **Seek bar thumb:** Draw as a narrow bright-green 3×10 CALayer line (Winamp posbar has a
  29×10 button thumb — simplify to a 3pt line for the CALayer approach).
- **Title scroll spacer:** Winamp uses `" *** "` as the separator between loop repetitions.
  Use the same separator for MANZO.
- **Pan center display:** When pan = 0, show "BALANCE" in the song title for 2s
  (Winamp behavior from `update_panning_text` — call `draw_songname` with "BALANCE CENTRE").
  Implement this via ManzoLCDView.showStatus(text:duration:) helper if scope allows.
- **No EQ+PL visual in Phase 8.1:** The EQ button region (x=219–265, y=58–70) is intentionally
  left empty — the EQ UI is deferred. The PL button already exists in statusView from Phase 8.

</specifics>
