## Fixed Issues

### CR-01: Integer overflow crash in `manzo_seek` call for long tracks

**Files modified:** `ManzoApp/ManzoApp/AppDelegate.swift`
**Commit:** eb742de
**Applied fix:** Changed `UInt64(t * 1000)` to `let tMs = UInt64(max(0, t) * 1000)` with a comment explaining the clamp. Clamping with `max(0, t)` before the `UInt64` cast eliminates the undefined-behavior crash path when `t` is negative. The `/1000.0` division at line 312 (`manzo_get_position`) was already present in the codebase from the prior commit (a35176f) and required no change.

### WR-01: Seek fires on zero-duration — fills seek bar to 100%

**Files modified:** `ManzoApp/ManzoApp/ManzoSeekBar.swift`
**Commit:** 9791ffb
**Applied fix:** Added `guard duration > 0 else { return }` as the first line of both `mouseDown(with:)` and `mouseDragged(with:)`. When no track is loaded (`duration == 0`), mouse events on the seek bar are now no-ops — `isDragging` is not set and `manzo_seek` is never called.

### WR-02: Pan normalization range mismatch — pan is always slightly off-center

**Files modified:** `ManzoApp/ManzoApp/AppDelegate.swift`
**Commit:** 53c7928
**Applied fix:** No code change was required (the normalization `v / 127.0` is correct for the configured `[-127, +127]` range). Added a four-line comment block above `manzo_set_pan(handle, v / 127.0)` documenting the intentional symmetric range choice versus the Winamp `[-128, +127]` signed-byte convention, and why the left/right extremes correctly map to `-1.0`/`+1.0`.

### WR-03: Poll timer not armed when user adds first track via file picker

**Files modified:** `ManzoApp/ManzoApp/AppDelegate.swift`
**Commit:** 69cd243
**Applied fix:** Inside the `onAdded` completion block in `openFilePicker()`, after scrolling to the last row, added a check: `if self.manzoHandle == nil { self.jumpToTrack(at: 0) }`. When the playlist was empty before the add and no handle is open, `jumpToTrack(at:0)` is called automatically, arming the poll timer and initializing the LCD/seek bar without requiring the user to manually double-click a row.

### WR-04: `PlaylistManager.move()` insert-index calculation incorrect for downward moves

**Files modified:** `ManzoApp/ManzoApp/PlaylistManager.swift`
**Commit:** 0790cc2
**Applied fix:** Replaced the single `else if from > currentIndex, to <= currentIndex` branch with two branches using `insertAt` (the post-removal adjusted index) instead of the raw `to` value:
- `insertAt < currentIndex` — item moved from below to strictly above current; increment.
- `insertAt == currentIndex` — item inserted at the exact same slot; current shifts down by 1.
This eliminates the off-by-one when dragging from below the current track to exactly the current track's row.

### WR-05: `PlaylistManager.load()` called from `init()` may run off main thread

**Files modified:** `ManzoApp/ManzoApp/PlaylistManager.swift`
**Commit:** 84e64a1
**Applied fix:** Added `dispatchPrecondition(condition: .onQueue(.main))` as the first line of both `load()` and `save()`. The class's thread contract ("all public methods called on main thread") is now enforced at runtime in debug builds, catching any future off-thread construction before silent data corruption can occur.
