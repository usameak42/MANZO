### Root Cause Analysis

The unit error is a single-line fix applied in two places:

1. `pollPlaybackState` line 312: `let position = Double(manzo_get_position(handle))`
   Fix: `let position = Double(manzo_get_position(handle)) / 1000.0`

2. `handlePrevButton` line 698: `let elapsed = manzoHandle.map { Double(manzo_get_position($0)) } ?? 0`
   Fix: `let elapsed = manzoHandle.map { Double(manzo_get_position($0)) / 1000.0 } ?? 0`

Note: The `onSeek` closure in `applicationDidFinishLaunching` already correctly converts seconds to milliseconds for the FFI call (`UInt64(t * 1000)`), so the seek bar's dragging output is correct — only the incoming position display is wrong.

### Gaps Summary

Two truths fail from a **single root cause**: `manzo_get_position()` returns `uint64_t` (milliseconds) but AppDelegate casts it directly to `Double` and treats it as seconds. This breaks:

- **Seek bar position display:** fill ratio is ~1000x too large; bar is immediately full for any non-trivial position
- **LCD time display:** `updateTime(position:)` formats position in seconds; passing 180000.0 (3 min in ms) yields "3000:00" instead of "3:00"
- **Smart prev threshold:** `elapsed > 2.0` fires after 2ms not 2s; smart prev never goes to previous track

The fix is a two-line change: divide `manzo_get_position` results by `1000.0` at the two call sites in AppDelegate. The `onSeek` closure already correctly handles the seconds→ms conversion outbound (`UInt64(t * 1000)`), so seek dragging sends correct values to the Rust core.

All other phase deliverables are correctly implemented: view files are substantive and P3-compliant, wiring is complete, build succeeds, and PlaylistManager.prev() is correct.
