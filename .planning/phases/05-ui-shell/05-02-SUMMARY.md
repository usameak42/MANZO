## Decisions Made

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] NSView.isOpaque is get-only — assignment in ManzoRootView.setupPanels() caused compiler error**
- **Found during:** Task 1 (build verification)
- **Issue:** `panel.isOpaque = false` on line 69 of ManzoRootView.swift failed with "cannot assign to property: 'isOpaque' is a get-only property" in macOS 26.4 SDK. NSView.isOpaque is a computed property with no setter — the plan's code inherited this from planning-time assumptions.
- **Fix:** Removed the assignment and replaced with a comment explaining that NSView returns false from isOpaque by default when wantsLayer=true and no backgroundColor is set (which is the desired transparent state).
- **Files modified:** ManzoApp/ManzoApp/ManzoRootView.swift
- **Verification:** BUILD SUCCEEDED after fix
- **Committed in:** d65560c (Task 1 commit)

**2. [Rule 1 - Bug] Phase 3 guard-return chains bypassed window setup when audio fixtures absent**
- **Found during:** Task 1 (code review of applicationDidFinishLaunching)
- **Issue:** The existing Phase 3 code used `guard FileManager.default.fileExists ... else { return }` which would skip the entire window setup block if test.mp3 was not found. This means the app would launch with no window visible when run in environments without audio fixtures.
- **Fix:** Refactored Phase 3 audio guards from guard-return to if/else so audio failure is logged and skipped but execution continues to the Phase 5 window setup block unconditionally.
- **Files modified:** ManzoApp/ManzoApp/AppDelegate.swift
- **Verification:** Window setup code is now unconditionally reached regardless of audio fixture state; BUILD SUCCEEDED
- **Committed in:** d65560c (Task 1 commit)
