## Panel Layout Contract

**Source: Winamp/Src/winamp/draw_main.cpp:draw_tbar() + CONTEXT.md D-08 (locked)**

Three named `NSView` subviews inside the root vibrancy view. All use Auto Layout — no frame-based layout.

| Panel name | Width | Height | Anchor | Phase 6 insertion point |
|------------|-------|--------|--------|-------------------------|
| `titleView` | 275 pt | 14 pt | top edge of root view | `titleView.layer` — CAGradientLayer sublayers |
| `bodyView` | 275 pt | 88 pt | fills middle (116 − 14 − 14) | `bodyView.layer` — CAGradientLayer sublayers |
| `statusView` | 275 pt | 14 pt | bottom edge of root view | `statusView.layer` — CAGradientLayer sublayers |

**Verification:** 14 + 88 + 14 = 116 pt (exact match to window height — no gap, no overlap).

**Swift constant declarations (required):**

```swift
private let kTitleBarHeight:  CGFloat = 14  // Winamp draw_tbar() update_area(0,0,275,14)
private let kStatusBarHeight: CGFloat = 14  // symmetric with title bar
private let kBodyHeight:      CGFloat = 88  // kWindowHeight − kTitleBarHeight − kStatusBarHeight
```

**Auto Layout rules for each panel:**

All three panels:
- `translatesAutoresizingMaskIntoConstraints = false`
- `wantsLayer = true`
- `isOpaque = false`
- `layer` is a plain `CALayer()` — do NOT set `CAGradientLayer` or any specialized layer type in Phase 5

`titleView` constraints: leading=root.leading, trailing=root.trailing, top=root.top, height=14  
`statusView` constraints: leading=root.leading, trailing=root.trailing, bottom=root.bottom, height=14  
`bodyView` constraints: leading=root.leading, trailing=root.trailing, top=titleView.bottom, bottom=statusView.top

## Vibrancy / Glass Layer Contract

**Source: spike-findings-MANZO/references/window-glass-architecture.md + CONTEXT.md D-07 (locked)**

### Root View (ManzoRootView)

| Property | Value | Constraint |
|----------|-------|-----------|
| Class | `NSVisualEffectView` subclass (`ManzoRootView`) | D-07 |
| Material | `ManzoGlassMaterial` named constant | D-01: exact case name unconfirmed until macOS 26 SDK |
| Blending mode | `.behindWindow` | D-07: ONE per window — ABSOLUTE MAXIMUM |
| State | `.active` | D-07 |
| wantsLayer | `true` | D-07 |
| cornerRadius | `0` — explicitly set to zero | D-07: Phase 5 is rectangular; Phase 6 may add radius |
| Role | `window.contentView` — this IS the content view | D-07 |

**Named constant (required — update in one place when macOS 26 SDK confirms the name):**

```swift
// D-01: Liquid Glass material — macOS 26 SDK name unconfirmed.
// Day-one action: 30-min Xcode prototype on macOS 26 SDK to find correct case.
// Expected: .glass or similar. Update ONLY this constant when confirmed.
private let ManzoGlassMaterial: NSVisualEffectView.Material = /* TBD: .glass */
```

**Minimum deployment target:** macOS 26. No `#available` fallback to macOS 15. Document in code comment on `ManzoWindow` class declaration.

### One-Per-Window Rule (NON-NEGOTIABLE)

Exactly ONE `NSVisualEffectView` with `.behindWindow` blending mode exists in the entire window hierarchy. No exceptions.

- Inner panels (`titleView`, `bodyView`, `statusView`) are `NSView` with `wantsLayer = true` — NOT `NSVisualEffectView`.
- Transient overlays (dropdown menus, tooltips) may use `.withinWindow` blending if needed — deferred to Phase 6+ when controls exist.
- Violation consequence: double-blur artifact (milky/washed-out glass) — silent failure, no crash.

## Drag Interaction Contract

**Source: Winamp/Src/winamp/main_nonclient.cpp:Main_OnNCHitTest() + CONTEXT.md D-11 (locked)**

### Pattern: Full-Chrome Drag

The entire window chrome is draggable from any unoccupied pixel — matching Winamp's `return HTCLIENT` for all non-button pixels.

**Implementation:**

Override `mouseDown(with:)` in `ManzoRootView`:

```swift
override func mouseDown(with event: NSEvent) {
    window?.performDrag(with: event)
}
```

**Fallthrough behavior:** Interactive controls added in later phases (Phase 6+: buttons, sliders) consume `mouseDown` in their own subviews first. Drag naturally falls through only to unoccupied chrome — no hit-test exclusion zones needed in Phase 5.

**Phase 5 drag target:** The entire 275×116 pt surface is draggable (no controls exist yet).

### Window Key / Main Override

Override on `ManzoWindow` (NSWindow subclass) — REQUIRED for `.borderless` windows:

```swift
override var canBecomeKey:  Bool { true }
override var canBecomeMain: Bool { true }
```

Without these overrides `.borderless` windows do not receive keyboard events (spike 006 landmine).

## Window Persistence Contract

**Source: CONTEXT.md D-12 (locked)**

| Mechanism | Value |
|-----------|-------|
| API | `window.setFrameAutosaveName("ManzoMainWindow")` |
| Storage | `UserDefaults` (AppKit built-in) |
| Trigger | AppKit saves automatically on move; restores on next launch |
| Manual observation | NOT required — single call handles save + restore |
| Autosave name | `"ManzoMainWindow"` — string literal; must be consistent across launches |

Call site: `applicationDidFinishLaunching`, after `orderFront`.

## Class / File Structure Contract

**Source: CONTEXT.md code_context + Claude's Discretion**

| Class | File | Role |
|-------|------|------|
| `ManzoWindow` | `ManzoApp/ManzoWindow.swift` | NSWindow subclass; overrides `canBecomeKey`, `canBecomeMain`; sets style mask, isOpaque, backgroundColor, hasShadow, collectionBehavior |
| `ManzoRootView` | `ManzoApp/ManzoRootView.swift` | NSVisualEffectView subclass; sets material, blendingMode, state, cornerRadius; overrides `mouseDown` for drag; adds and constrains three panel NSViews |

**Wiring location:** `AppDelegate.applicationDidFinishLaunching` — instantiate `ManzoWindow`, set `contentView` to `ManzoRootView`, call `orderFront` and `setFrameAutosaveName`.

No `NSWindowController` or `NSViewController` in Phase 5 — AppDelegate owns the window directly (established pattern from Phases 1–4).

**xcodegen registration requirement:** Both new Swift files must be listed in `ManzoApp/project.yml` under `targets.ManzoApp.sources`. The existing `sources` entry uses path-based glob (`path: ManzoApp`) which auto-picks up `.swift` files in the directory — new files placed in `ManzoApp/ManzoApp/` are automatically included. Verify with `xcodegen generate` after file creation.
